# Скриншоты опубликованной 0.39.0

Workflow `Capture published 0.39 screenshots` запускается вручную в GitHub Actions. Он скачивает публичный ZIP 0.39.0, проверяет SHA-256 и снимает реальный WPF-интерфейс опубликованной DLL в Windows. Исходники приложения из текущей ветки не пересобираются.

Драйвер ждёт загрузки каталога и видимых постеров, переключает темы и открывает сериалы. `capture-info.json` содержит версию, хэш DLL, названия карточек и количество загруженных постеров. После захвата проверьте PNG визуально: недоступная обложка может остаться незагруженной даже после ожидания.

Для локального запуска нужны Windows и .NET 10 SDK:

```powershell
dotnet build scripts/screenshots/CaptureReleaseScreenshot.csproj -c Release -p:ReleaseDirectory=C:\Kachalka-0.39
dotnet scripts/screenshots/bin/Release/net10.0-windows/CaptureReleaseScreenshot.dll C:\Kachalka-0.39 C:\screenshots
```

Настройки захвата изолированы. В GitHub передаются только PNG и очищенные метаданные; профиль, ключи и настройки не загружаются. Временный черновик `docs-preview-<run-id>` предназначен для просмотра и удаляется после сохранения одобренных снимков в документации. Действующий релиз и его файлы workflow не изменяет.

Файлы в `distribution/assets/0.39/` относятся именно к 0.39.0. Очередь загрузок показана на демонстрационных задачах; её снимок и диалог сопряжения получены при Windows-проверках того же релизного коммита `d1b12a7a8814ea0f51173cb25706d4f04f7a772a`.
