# Поиск и рекомендации: 0.44.16

## Причины

- Локальный поиск проверял начало строки; сводная выдача ограничивалась до ранжирования и могла сохранять нерелевантные результаты.
- Источники ожидали все названия через `Task.WhenAll`: один зависший запрос мог лишить источник уже полученных ответов. Игровой RuTor возвращал первую успешную группу вместо объединения названий.
- Knaben v1 отдавал первые 75 строк всех трекеров; клиент затем отбрасывал неподходящие трекеры.
- Windows выбирал рекомендацию до фильтрации. Mac получал только один глобальный флаг, поэтому при выборе другой студии рекомендованная строка исчезала. Наличие русского многоголосого перевода ошибочно называлось `russianDub` в IPC.
- Дубляж с 1–19 отдающими исключался целиком даже при известном HD.

## Исправления

- `CatalogSearch`: общий ранжировщик локальных каталогов и сводного поиска; IMDb ID/URL, проверенные переводы, все слова, год, раскладка, ограниченный fallback одной опечатки. Поисковая нечёткость не используется для объединения идентичностей.
- `ReleaseAliasSearch`: до четырёх названий, два worker, индивидуальные сроки и сохранение успешных ответов. Общие ограничения источников и размеров ответов сохранены.
- `KnabenSource`: документированный GET `/v2/search`, `sf=title`, `s=150`, `t=rutracker` для видео, `rutracker,thepiratebay` для игр. Флаги unsafe/xxx/dead не включены. Прежний лимит частоты сохранён.
- `ReleaseRecommendation.Ranked`: единый порядок допустимых кандидатов. Положительное число отдающих и известное HD обязательны для расширенного выбора дубляжа; настройка минимального качества остаётся в силе.
- Mac получает необязательный `recommendationOrder`, выбирает кандидата после фильтров и согласует с ним главную кнопку. Старый IPC остаётся совместимым. `russianDub` означает именно дубляж; фильтр русской озвучки продолжает включать многоголосую.
- Backrooms: `tt26657236`, 2026, TMDB `1083381`, «Закулисье реальности». Подтверждено живым TMDB API; секреты не сохранены.
- Серверные изменения: проверенный alias и Knaben v2. Они попадут на Sites через существующую автоматизацию после её собственных обязательных проверок; выпуск приложения сам по себе не является подтверждением публикации сайта.

## Проверки перед CI

- Полный `desktop-core-tests`: пройден, включая алиасы, фильтрацию, typo/layout, дедлайны, ограничение параллелизма, реальную передачу файлов и HTTP-управление с телефона.
- Сборки WPF и desktop-host: пройдены; WPF сохраняет четыре прежних nullable-предупреждения в FeaturedPortal/GamesSmoke.
- `title-identity.mjs`, `release-performance.mjs`, TypeScript: пройдены. Контракт v2 проверяется отдельно; fixture сохраняет только публичные поля ответа.
- На 15 000 прогретых локальных карточек проверочный поиск занял около 8 мс в этой среде. Это измерение теста, не обещание скорости внешних источников.
- Живой IPC Backrooms: 89 уникальных результатов до и после изменения, семь от RuTracker/Knaben. При фильтре Flarrow Films допустимый кандидат — 4K, 21 отдающий; есть также HD-кандидаты с меньшим числом отдающих. Увеличение общего числа результатов на этом фильме не заявляется.
- Без фильтров выбранная HDrezka-раздача уже содержит `Dub` в названии. Новый код не объявляет одну студию официальной и не подменяет пользовательский выбор студии.
- Тема RuTracker `6900356` не обнаружена в текущей выдаче Knaben. Нельзя гарантировать полноту стороннего индекса или фактическую скорость загрузки по числу отдающих.
- Для Mac добавлены четыре теста: рекомендация в выбранной студии/качестве, отсутствие подходящих кандидатов, различие MVO/Dub, согласованность основной кнопки со списком. Их выполнение и нативные окна проверяются релизным CI на реальных Mac.
