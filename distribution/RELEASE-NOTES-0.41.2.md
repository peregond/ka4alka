# Качалка 0.41.2

- Поиск объединяет карточки русского каталога и IMDb, если они описывают одну работу. Предпочтение сохраняется за карточкой каталога, её адресом и идентификатором; альтернативные названия и метаданные объединяются.
- South Park / «Южный Парк» и Solar Opposites / «Обратная сторона Земли» / «Солнечные противоположности» связаны по IMDb ID. Русские варианты подтверждены живым TheTVDB v4. Используется общий файл title-aliases.json; неподтверждённые английские алиасы в него не включены.
- Алиасы других работ приходят вместе с метаданными TheTVDB и TMDB и сохраняются в локальном индексе. IMDb-карточки также сохраняются, поэтому повторный поиск по переводу не начинает сопоставление с нуля. Разные разделы, годы и конфликтующие IMDb ID не объединяются.
- Сохранённые фильмы продолжают распознаваться после объединения русской и английской карточек; удаление из сохранённого учитывает связанные карточки.
- Раздачи сопоставляются со всеми известными названиями; повторяющиеся torrent-идентификаторы остаются одной строкой. NNM-Club и MegaPeer ищут названия параллельно, не последовательно. Число вариантов ограничено четырьмя.
- Подготовленные слова и названия повторно используются локальным поиском. Удалено прежнее отдельное правило дедупликации IMDb по одному названию и году.
- Сервер сохраняет положительные ответы метаданных в D1/SQLite на неделю, чтобы переживать перезапуски без повторных запросов. Добавлена отдельная таблица title_metadata; существующий каталог и раздачи не пересоздаются. Сбой базы не скрывает полученный ответ API.
- Дополнительное сопоставление неизвестных IMDb-карточек ограничено двумя параллельными запросами и общим бюджетом три секунды. При недоступном источнике остаются исходные результаты; неоднозначные работы сохраняются раздельно.

Сохранены изменения опубликованной 0.41.1: прокрутка сезонов и серий, восстановление обложек, все оптимизации 0.41.0. Для серверной части Sites нужна публикация новых исходников и добавочной SQL-миграции; Railway применяет её при запуске. API совместим со старым приложением.

Локальный замер подготовленного поиска по 4210 записям и девяти запросам: 94 мс против 461 мс, выделения памяти 7,3 МБ против 24,1 МБ. Совпадение обычных результатов проверено. Это измерение прогретого цикла поиска на Linux, не скорости загрузки сети или всего приложения. Данные — assets/performance/0.41.2.json.
