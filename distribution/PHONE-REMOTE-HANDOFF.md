# Управление загрузками с телефона

Общий код для Windows и macOS: `lan-core/PhoneRemoteServer.cs`, `native/PhoneRemoteCatalog.cs`.

## Использование

1. В настольном приложении выбери папку загрузок.
2. Настройки → Устройства в сети → Подключить телефон.
3. На телефоне в той же домашней Wi-Fi сети отсканируй QR-код камерой. Браузер подключится автоматически, вводить код не нужно. QR одноразовый и действует две минуты.
4. Альтернатива: открой показанный адрес `http://<локальный-IP>:45834/` и введи ручной код. При нескольких сетевых адресах можно выбрать адрес для QR и скопировать обычную ссылку.
5. Найди фильм, сериал или игру, выбери раздачу, подтверди скачивание на компьютере. Можно также вставить magnet-ссылку. Во вкладке «Загрузки» доступны пауза и продолжение. Для удалённых файлов есть отдельное подтверждённое «Скачать заново».

Приложение и компьютер должны оставаться включёнными. Кнопка «Отключить все телефоны» закрывает сервер и отзывает все сессии. При следующем запуске доступ выключен. Для следующего телефона нажми «Подключить телефон» ещё раз. Если адресов несколько, используй адрес Wi-Fi/Ethernet домашней сети. Гостевая Wi-Fi сеть может запрещать связь между устройствами. В Windows можно использовать существующую кнопку разрешения брандмауэра для частной сети; правила автоматически не меняются.

Локальная страница работает по HTTP: это режим для доверенной домашней сети, без публикации в интернете, проброса портов или настройки отдельного сайта. Она открывается прямо с компьютера; публичный HTTPS-лендинг не обращается к частным HTTP-адресам.

## Границы доступа

- Отдельное явное включение; старое mTLS-сопряжение компьютеров не меняется.
- Только IPv4-адреса своей частной подсети; loopback разрешён исключительно тестовой опцией.
- Host должен точно совпадать с адресом интерфейса и портом. Чужой/opaque Origin отклоняется, CORS не включён.
- Только JSON POST, Bearer-сессия в памяти сервера и sessionStorage браузера, без cookie. Срок сессии — восемь часов, максимум восемь телефонов. Выход отзывает текущую сессию.
- Код создаётся криптографическим генератором, пять попыток на адрес и двадцать на окно сопряжения. Новый код выдаётся только локально в приложении.
- QR содержит тот же одноразовый код в URL fragment `#pair=…`: fragment не отправляется HTTP-серверу и сразу удаляется через replaceState до первого запроса. Пара подтверждается существующим `/pair`; после использования/истечения QR скрывается. Генерация локальная, без внешнего QR-сервиса: QRCoder на Windows и Core Image на Mac. Изображение пересоздаётся только при изменении адреса/кода.
- API: каталог, раздачи, добавление загрузки, список состояния и три команды `/api/control`: pause, resume, redownload. Нет настроек, удаления файлов, запуска программ или произвольного IPC. Задание определяется существующим ID очереди.
- pause/resume задают желаемое состояние вместо toggle, поэтому повтор запроса безопасен. redownload требует `confirmed:true` и текущего `FilesMissing`; повтор после начала загрузки ничего не перезапускает. Обычное resume сохраняет защиту отсутствующих файлов.
- Ручное добавление принимает только валидные magnet-ссылки. Файловые пути и произвольные HTTP-адреса недоступны. При выборе раздачи используется известный серверу результат поиска.
- Повторное добавление того же infohash возвращает существующую задачу, включая задачи с отсутствующими файлами; автоматической повторной загрузки нет.
- Ограничены число соединений, размер заголовков/тела, длительность запроса, объём памяти каталога. Поисковые запросы выполняются последовательно, без автопоиска при каждой букве и без фонового опроса телефона.
- CSP, textContent вместо HTML из источников, no-store, запрет фреймов и отсутствие внешних скриптов.

## Проверки

- `dotnet run --project lan-tests -c Release`: реальные HTTP-проверки сопряжения/Origin/Host/сроков/отзыва/размеров и существующие mTLS-проверки.
- `dotnet run --project desktop-core-tests -c Release`: реальное скачивание с локального сидера, запущенное через HTTP, проверка SHA-256, повторов, запрещённых источников и невыбранной папки.
- `python scripts/test-desktop-ipc.py`: старт/остановка и повторное открытие серверного порта через движок.
- `scripts/test-phone-browser.mjs`: мобильные Chromium и WebKit с профилем iPhone, RU/EN, обычное/запрещённое sessionStorage, подключение → каталог → раздача → загрузки, сохранение сессии при обновлении страницы, выход, ширина 390px. WebKit проверяет совместимость движка Safari; физический iPhone в CI не подключён. При запрете sessionStorage доступ сохраняется в памяти до закрытия страницы.

Windows и macOS используют свои системные настройки/кнопки и один общий сервер/каталог/очередь. Нативные сборки и матрица окон проверяются штатными release workflows.
