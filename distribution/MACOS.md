# Windows и macOS: один продукт и один выпуск

Windows сохраняет нативный интерфейс WPF. macOS использует SwiftUI и AppKit, системные шрифты, меню, выбор папки, уведомления и Finder. В обоих приложениях нет Electron, WebView или локального HTTP-сервера.

## Общая логика

`desktop-core/Kachalka.DesktopCore.csproj` компилирует исходники непосредственно из `native/`: каталог, идентичности русских и английских названий, подборки и награды, Steam, метаданные, источники раздач, очередь MonoTorrent, восстановление сети, контроль места и удалённых файлов, диагностику и LAN. Windows продолжает компилировать эти же файлы в своём WPF-проекте. Исправление общего источника применяется сразу к обоим приложениям.

Mac запускает самодостаточный `Kachalka.Engine` и общается с ним через унаследованные stdin/stdout. Никакие порты для интерфейса не открываются. Изменяемое состояние движка обслуживает один контекст; изображения декодируются отдельно, с ограничением памяти, объединением повторных запросов и отменой работы для невидимых карточек. Обновления очереди не перерисовывают каталог.

Новые экранные функции нужно реализовывать и проверять в обоих нативных интерфейсах. Общий движок не создаёт кнопки SwiftUI автоматически. При добавлении функции обновляйте её Windows- и Mac-сценарии, а команды и модели сохраняйте совместимыми. Не создавайте отдельную ветку развития или номера версий Mac.

## Единая публикация

Номер версии задаёт `native/Kachalka.csproj`; сборка Mac и его движка читают его оттуда. `.github/workflows/release.yml` выпускает один тег с установщиком Windows, Windows ZIP, Apple Silicon DMG/ZIP и Intel DMG/ZIP.

Публикация требует успешных проверок WPF, общего движка на Windows и Linux, нативного приложения и настоящих торрент-загрузок на обоих типах Mac. Пакеты Mac имеют отдельный подписанный манифест и каталоги компонентов. Windows использует прежний формат обновлений. Публичный релиз становится доступен сразу для всех платформ; при ошибке одной сборки он остаётся черновиком.

`publish-release.yml` повторно проверяет подписи, состав пакетов, единый номер версии, исходный коммит тега и завершённые задания исходного release workflow. Поэтому отдельный ручной запуск публикации также не пропускает частичный выпуск, начиная с 0.44.0.

## Mac: сборка и установка

Требуются macOS 14+, Xcode Command Line Tools, .NET SDK 10 и Python 3 только для сборки. Пользователю устанавливать SDK или .NET не нужно.

```bash
bash scripts/macos/build.sh arm64   # Apple Silicon
bash scripts/macos/build.sh x64     # Intel
```

Результаты находятся в `dist/macos-ARCH/`. В DMG находится приложение и ссылка на Applications. Перетащите Ka4alka в Applications и откройте его; при первом запуске выберите папку для загрузок. Внутри создаётся `Ka4alka`.

Без настроенного Developer ID используется ad-hoc подпись, проверяемая при сборке. Это не нотариализация Apple: Gatekeeper может потребовать разрешить запуск приложения в «Системные настройки → Конфиденциальность и безопасность». Для обычного подтверждённого Apple запуска потребуются сертификат Developer ID и нотариализация; они не заменяются подписью манифеста обновлений.

Настройки и очередь Mac находятся в `~/Library/Application Support/Kachalka`. Путь может быть переопределён `KACHALKA_DATA` для независимых тестовых профилей. Настройки и личные данные двух компьютеров автоматически не синхронизируются. Подтверждённые устройства в одной локальной сети могут отправлять друг другу запросы загрузок.

Игровой раздел сохраняет существующий каталог **игр для Windows**. Mac может скачать файлы или отправить загрузку на Windows-компьютер. Само приложение не запускает Windows-игры и не устанавливает средства совместимости.

## Проверки

```bash
dotnet run --project desktop-core-tests/Kachalka.DesktopCoreTests.csproj -c Release
dotnet run --project mac-update-tests/Kachalka.MacUpdateTests.csproj -c Release
dotnet build desktop-host/Kachalka.DesktopHost.csproj -c Release
python3 scripts/test-desktop-ipc.py
cd macos && swift test -c release
```

Для теста замены настоящего подписанного приложения задайте `KACHALKA_TEST_APP` абсолютным путём к собранному `Ka4alka.app`. UI-сценарий запускается через `Ka4alka.app/Contents/MacOS/Ka4alka --smoke-test OUTPUT`; он создаёт снимки настоящих окон и `checks.json`.
