# Широкие фоны фильмов и сериалов

Баннеры главной страницы и карточек используют отдельные горизонтальные изображения TMDB. Обычные вертикальные постеры остаются в каталоге, загрузках и карточках; они больше не превращаются в фон баннера. При отсутствии фона главная страница показывает спокойный фон и отдельный постер (в узком окне постер скрывается, чтобы не перекрывать текст). В облегчённом режиме запросов фонов нет.

## Подключение

1. Создать личный аккаунт на <https://www.themoviedb.org/signup> и подтвердить почту.
2. Открыть <https://www.themoviedb.org/settings/api>, запросить Developer API для некоммерческого использования. Бесплатность зависит от характера использования: коммерческое приложение требует отдельного согласования с TMDB.
3. Указать название приложения «Качалка», адрес <https://ka4alka-online-new.peregon.chatgpt.site/> и описание: «Desktop catalogue of movies and TV series; TMDB landscape artwork is used for featured banners». Проверить и принять условия самостоятельно.
4. Скопировать **API Read Access Token** (Bearer), а не короткий API Key v3. Добавить его как секрет **`TMDB_READ_TOKEN`** в среду опубликованного сайта. Не записывать ключ в исходники, `.openai/hosting.json`, настройки пользователей, приложение или публичный каталог.
5. Для проверки из Codex добавить тот же секрет в подготовленное поле облачной среды. Черновик настроек среды разрешает `api.themoviedb.org`, `image.tmdb.org`, `developer.themoviedb.org`, `www.themoviedb.org`. Сохранение черновика само по себе не применяет настройки: требуется сохранить и опубликовать среду. Это не настраивает секрет опубликованного сайта автоматически.
6. Опубликовать обновлённый `web-index/`. Проверить `/api/backdrop?id=movies:<существующий-slug>`: ответ содержит исходный `id` и `backdrop` с полями `source`, `tmdbId`, `url` либо `backdrop:null`. `/api/backdrop-image?file=<имя-файла-с-начальным-слешем>` возвращает проверенный JPEG.

В настройках приложения добавлено указание TMDB и обязательная фраза: «This product uses the TMDB API but is not endorsed or certified by TMDB». Перед публичным выпуском подключённой интеграции необходимо также добавить актуальный одобренный логотип из [правил атрибуции TMDB](https://developer.themoviedb.org/docs/attribution), проверить условия использования и доступ к настоящему API.

## Поиск и скорость

- Ключ используется исключительно сервером в заголовке Authorization к фиксированному адресу TMDB. Приложение и пользователи получают публичные ссылки на изображения.
- Сервер принимает только ID карточки своего каталога (D1, ежедневный общий каталог или стартовый снимок). Произвольные названия и адреса клиента не передаются в TMDB.
- При наличии IMDb ID используется точное сопоставление через `/find`. Иначе нужны точное русское/оригинальное название и совпадающий год. Неоднозначные совпадения пропускаются. Фильмы и сериалы ищутся отдельно.
- Выбираются горизонтальные изображения шириной от 780 px, с пропорцией 1,6–2,5. Сначала фоны без текста, затем русские и английские. Загружается размер `w1280`; изображения больше 2 МиБ не принимаются.
- Изображения доступны через сервер сайта, поэтому приложению не требуется напрямую подключаться к домену изображений TMDB. Это не гарантирует доступность сайта из любой сети.
- Сервер объединяет одинаковые запросы, ограничивает параллельные запросы и использует кэш в памяти; заголовки разрешают CDN-кэш. Приложение хранит результат на диске: найденный фон — 7 дней, подтверждённое отсутствие — 1 час. Старый найденный фон используется при сбое сети до 30 дней. Ошибка сервера не записывается как подтверждённое отсутствие.
- Запрос и декодирование выполняются вне потока интерфейса. Изображения загружаются только около видимой области; при уходе с экрана запрос отменяется. Общий запрос отменяется, когда ушёл последний подписчик. Очередь загрузки постеров ограничена двумя операциями.

## Проверки

```bash
dotnet run --project backdrop-tests/Kachalka.BackdropTests.csproj -c Release
cd web-index
node tests/tmdb-backdrop.mjs
node tests/shared-catalog.mjs
npx tsc --noEmit --incremental false
```

Кросс-компиляция WPF: `dotnet build tests/Kachalka.Tests.csproj -c Release -p:EnableWindowsTargeting=true`. Реальные проверки UI и совместной отмены запросов выполняются на Windows существующими `--design-smoke-test` и `--cover-viewport-smoke-test`; в этой ветке они включены в Windows CI. Linux-сборка не доказывает, что UI-проверки прошли.

До появления ключа сервер отвечает 503 без раскрытия настроек. Релиз приложения с активным TMDB не публикуется до проверки API, атрибуции и Windows UI.
