# Производительность на слабых ноутбуках

Изменения после 0.41.2:

- Существующий «Лёгкий режим» автоматически предлагается поведением по умолчанию на компьютерах с двумя логическими процессорами или доступной памятью до 4 ГБ. Сохранённый ручной выбор имеет приоритет. Режим отключает декоративные фоны, анимации скелетонов и появление обложек с анимацией; обложки, поиск и загрузки остаются доступны.
- На слабом компьютере или в ручном лёгком режиме одновременно обрабатывается одна обложка и один запрос фоновых рейтингов. Для фильмографии — два поиска вместо пяти. Открытая карточка сохраняет отдельную очередь метаданных.
- Кэш декодированных обложек ограничен 12 МиБ на слабых компьютерах/в лёгком режиме и 32 МиБ на остальных, с вытеснением по последнему использованию. Это лимит кэша, а не всей памяти процесса. Изображения вдали от видимой области освобождаются контролами.
- Одинаковые видимые обложки и рейтинги объединяют запросы. Уход одного подписчика не отменяет работу другого; уход последнего отменяет ненужную работу.
- Уменьшенные PNG сохраняются на диск по размеру декодирования. Они подпадают под существующий общий лимит дискового кэша; исходник позволяет восстановить повреждённую миниатюру без повторного скачивания.
- Результаты поиска фильмов, сериалов и IMDb появляются по мере ответа. Последующие объединение и сортировка выполняются в фоне. Отмена прекращает ожидание даже источника, который не соблюдает cancellation.
- Восстановление раздач из дискового кэша перенесено из потока интерфейса. При выходе из карточки отменяются незавершённые поиск раздач и метаданные; завершённые результаты сохраняются.

## Проверка

`catalog-text-tests` проверяет фактические классы памяти/совместных запросов, ранние результаты поиска и отмену. Windows-команда `dotnet run --project tests/Kachalka.Tests.csproj -c Release -- --performance-only` дополнительно проверяет реальную WPF-декодировку, сохранение миниатюр, восстановление повреждённого кэша и независимое завершение источников раздач.

Workflow `Verify bounded background work and image loading` запускает эту команду и реальные WPF-сценарии cover-viewport, person-performance и startup-performance. Результаты сохраняются в артефактах `performance-2cpu-<SHA>` и `performance-4cpu-<SHA>`. Матрица ограничивает число процессоров, видимых .NET; частоту CPU и реальную ОЗУ ноутбука она не эмулирует.

Тесты на Windows CI не заменяют измерение на физическом слабом ноутбуке. Нет обещания конкретного FPS или ускорения сети: удалённые источники сохраняют собственную задержку. Общая память включает видимые контролы, торрент-движок и другие данные, помимо кэша обложек.
