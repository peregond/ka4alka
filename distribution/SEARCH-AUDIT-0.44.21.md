# Аудит поиска 0.44.21

Проверен полный известный текстовый каталог от 22 октября 2026 года: **4 235 карточек (3 632 фильма и 603 сериала)**, **7 787 названий и альтернативных имён**, **16 881 вариант запроса**. SHA-256 проверенного JSON: `13e09efca97b3e2f9d52c5dc6fc35af61ee736e43749bc1e329de5bec8118f3a`.

Для каждого известного имени проверены обычное написание, канонически эквивалентное Unicode NFD и название с годом. Desktop-аудит использует настоящий `CatalogSearch.Find` на всём разделе и проверяет наличие исходной карточки в результатах; серверный аудит проверяет реальный локальный сопоставитель. Это не проверка всех существующих фильмов в интернете и не подтверждение наличия торрентов.

До исправления канонической нормализации: **1 281 неуспешный вариант запроса, 1 234 затронутые карточки**. После исправления: **0** в обоих аудитах; desktop-проверка всего массива заняла около 10 секунд. Никакие произвольные похожие названия не объединяются: нормализация Unicode не меняет идентичность произведения.

Вторая причина независима от Unicode: неполный каталог 2011–2026 годов возвращал один документальный фильм или позднюю часть франшизы, после чего поиск не обращался к источнику. В ограниченной живой выборке из 24 запросов опубликованный сервер пропускал результаты источника в 18 запросах. Исправленный обработчик проверен на тех же 24 запросах с настоящими сетевыми ответами и проверенным текстовым каталогом вместо удалённого хранилища: **24 из 24 полны относительно результатов источника**, пропусков нет. Публичный сайт до отдельной публикации сервера остаётся на прежнем обработчике.

Приложение самостоятельно объединяет основной поиск с прямым источником в рамках существующего десятисекундного дедлайна. Windows показывает доступные результаты по мере поступления. Недоступность дополнительного источника не уничтожает найденные карточки. Новый профиль движка проверен запросами «гарри поттер» и `Harry Potter`: все восемь основных частей, локализованные названия и точные IMDb ID.

Ограничения покрытия: в текущем массиве 672 карточки без оригинального названия и 1 907 без IMDb ID. Отсутствующие переводы нельзя проверить как известные имена; аудит не подставляет вымышленные метаданные. Лимиты выдачи и недоступные внешние ответы отмечаются отдельно от ошибок сопоставления.

Воспроизведение:

```sh
dotnet run --project catalog-audit -c Release -- --catalog catalog.json --report test-output/native-search-audit.json
cd web-index
node tests/audit-catalog-search.mjs --catalog ../catalog.json --report ../test-output/server-search-audit.json
node tests/catalog-search.mjs
cd ..
python3 scripts/audit-catalog-live.py --catalog catalog.json --report test-output/live-search-audit.json
```

Без `--catalog` проверяется встроенный каталог. Полный локальный аудит не делает сетевых запросов и не запускается при обычном старте приложения. Проверки добавлены в CI ветки, выпуск приложения и workflow обновления каталога; расписание GitHub использует workflow из основной ветки, поэтому его новая ежедневная версия начнёт работать после переноса туда. Живой аудит ограничен 24 запросами и двумя параллельными проверками, его отчёт сохраняется отдельно. Ошибка обязательного локального аудита останавливает публикацию нового каталога, сохраняя предыдущий.
