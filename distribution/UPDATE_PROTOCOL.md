# Обновления «Качалки» с 0.19.0

Клиент читает https://github.com/peregond/ka4alka/releases/latest/download/latest.json и соседний latest.sig. Метаданные подписываются RSA/SHA-256 (PKCS#1 v1.5) над точными байтами JSON. Публичный ключ update-core/update-public.pem встроен в приложение и установщик обновлений.

Формат 1: schemaVersion=1, appId=kachalka, channel=stable, platform=win-x64, minimumWindows=10, трёхкомпонентная version, automaticInstallationAvailable=true. package содержит url, fileName=Kachalka-win-x64.zip, точный size, sha256 и format=portable-zip; releaseNotesUrl указывает на тег той же версии. Архив размещается только по адресу https://github.com/peregond/ka4alka/releases/download/v<VERSION>/Kachalka-win-x64.zip.

После проверки подписи клиент предлагает только более новую версию. HTTPS-перенаправления разрешены внутри release-маршрутов этого репозитория и на release-assets.githubusercontent.com. Размер загрузки ограничен 512 МиБ, распакованный объём — 2 ГиБ, число записей — 10000. Плохая подпись, размер, SHA-256, версия DLL, дубли, ссылки, зарезервированные Windows-имена и выход ZIP-пути за папку распаковки блокируют установку.

Проверка при запуске и автоматическая загрузка/установка при выходе включены по умолчанию и отключаются в настройках. Ручные действия — «Проверить обновления», «Что нового», «Обновить и перезапустить». Проверка ограничена 20 секундами, скачивание — 15 минутами; ошибка сети не блокирует каталог и очередь.

Временные файлы хранятся в %LOCALAPPDATA%/Kachalka/updates/<id>. Отдельный самодостаточный установщик ждёт завершения исходного процесса (PID и время запуска), повторно проверяет подпись и архив, подготавливает новую папку на том же диске и заменяет папку приложения переименованием. Настройки и очередь сохраняются до выхода, торрент-движок останавливается. Новая версия должна подтвердить появление окна за 45 секунд; без подтверждения она останавливается и восстанавливается предыдущая папка. Результат записывается в result.txt. Предыдущие резервные папки остаются рядом с папкой приложения; их можно убрать вручную после проверки новой версии.

Если система блокирует запись или откат, резервная папка сохраняется для ручного восстановления. Обновление не запрашивает повышение прав. Папка загрузок и пользовательские данные должны находиться вне папки приложения.

Для Windows-инсталляции используется NSIS: Kachalka-Setup-<VERSION>.exe, установка для текущего пользователя, ярлыки и удаление в настройках Windows. Удаление сохраняет настройки, очередь и загруженные файлы. Версия 0.18 обновляется до 0.19 вручную — в старом клиенте нет проверки обновлений.

Проверки ядра запускаются и на Linux: dotnet run --project update-tests/Kachalka.UpdateTests.csproj -c Release. Windows-запуск, установка/удаление, блокировки файлов и полный переход между двумя реальными версиями проверяются на Windows отдельно.
