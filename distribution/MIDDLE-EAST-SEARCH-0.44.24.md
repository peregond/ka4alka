# Поиск «Однажды на Ближнем Востоке», 0.44.24

Основа — свежая опубликованная 0.44.23 и коммит ветки `685e4db`, включая последние изменения дизайна Mac.

TMDB подтвердил точное произведение: movie ID `1391021`, IMDb `tt34386754`, дата `2026-08-08`, русское название «Однажды на Ближнем Востоке», английское `Once Upon a Time in the Middle East`, оригинальное китайское `欢迎来龙餐馆`. В каталоге было только русское название и транслитерация `Huan ying laai long can guan`.

Проверенные запросы по русскому названию и транслитерации не дали подходящих результатов в RuTor, NNM-Club и Knaben. Английский запрос в Knaben вернул видеораздачу The Pirate Bay:

- `Once.Upon.A.Time.In.The.Middle.East.2026.HC.1080p.WEB.H264-NGP`;
- info hash `F81D21727E4DB6E7E70290230C230570108473BB`;
- 3 307 124 817 байт, 411 сидов в сохранённом ответе (счётчик меняется со временем);
- https://thepiratebay.org/description.php?id=84302551;
- описание источника указывает китайскую аудиодорожку и вшитые китайские/английские субтитры, а также тот же IMDb ID. Русская дорожка не подтверждена. Медиафайл не скачивался.

Причины пропуска: отсутствие английского поискового имени и ограничение нативного Knaben-провайдера трекером RuTracker для фильмов. Прямой APIBay-запрос по английскому имени в этой проверке был пустым, поэтому уже существующий отдельный провайдер The Pirate Bay не компенсировал ограничение индекса.

Исправление использует два известных трекера в одном запросе Knaben, прежние лимиты 150 результатов, четыре имени, два обработчика имён и интервал запросов. Произвольные трекеры, неверные годы, посторонние фильмы и игровые категории в фильмах остаются исключёнными. Смена имени статуса на Knaben отражает фактический охват; бюджет фоновой проверки качества сохранён.

В присланной ссылке заголовок содержит остаточные `%20` после обычного декодирования. Общий путь открытия ссылки уже восстанавливает каноническое название по точному адресу страницы. Регрессионная проверка теперь проходит этот путь целиком и проверяет обратное создание ссылки. Повторное декодирование произвольных значений не добавлялось: буквальные последовательности процентов в названиях продолжают сохраняться.

Проверено локально: общий набор desktop-core, сборка Windows-тестов, сборка движка, IPC-проверки, TypeScript, серверные тесты и сборка. Живая проверка провайдера и отдельный свежий IPC-профиль нашли указанную раздачу через присланную ссылку; загрузки при этом не добавлялись. Серверный тест использует тот же сохранённый публичный ответ индекса, без ключей и внешних зависимостей. Новый случай включён в обязательные проверки выпуска и архива Sites.

Воспроизведение живого поиска:

```sh
dotnet run --project desktop-core-tests -c Release -- --probe-middle-east
```

Для сервера Sites достаточно опубликовать новый `web-index/app/data/title-aliases.json` вместе с проверенным текущим исходным деревом. Приложение ищет через собственный провайдер и не требует предварительного обновления Sites.
