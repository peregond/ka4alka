# Текстовый каталог приложения

Каталог показывается из встроенного снимка или последнего проверенного локального файла. Сетевая проверка запускается отдельно и не задерживает каталог и локальные результаты поиска. Описания, рейтинги, жанры, страны и участники фильма входят в снимок; картинки представлены только адресами. Изображения и раздачи загружаются существующими механизмами по мере необходимости.

## Сервер и сборка

`catalog-daily.yml` обновляет публикацию `catalog-data` ежедневно около 05:00 UTC. Коллектор восстанавливает предыдущую полную библиотеку, добавляет новые названия и сохраняет уже собранные описания и участников. По умолчанию он начинает не более 1000 проверок карточек за 600 секунд, с четырьмя параллельными запросами. Проверки старых сведений распределяются по очереди; недоступный источник не стирает прежние данные. IMDb обновляется по идентификатору из официального набора рейтингов.

Публикация состоит из неизменяемого `catalog-<revision>.json.gz`, `manifest.json` и совместимого `catalog.json`. Manifest переключается после проверки опубликованных файлов. Клиент и сборка проверяют адрес, SHA-256, размер и распаковку. Поддерживаются максимум 15000 записей и 32 МиБ JSON; снимок должен содержать не менее 2000 фильмов и 300 сериалов. Повреждённая или неполная публикация не заменяет локальную библиотеку.

Перед выпуском `release.yml` скачивает проверенный серверный снимок и запускает `scripts/bundle-catalog.py`. Полные данные становятся встроенным `seed.json`, первые 40 записей каждого раздела — облегчённым `starter.json`, а подборки — отдельным встроенным ресурсом. Изменение этих ресурсов требует новой Windows-проверки; результат проверки исходного дерева повторно не используется.

Для первого выпуска с этой схемой сначала нужен успешный запуск `catalog-daily.yml`, публикующий manifest и архив. До него сборка выпуска остановится на отсутствии проверенного снимка.

## Обновление приложения

После успешной проверки снимка приложение сохраняет `LastCheckedUtc` и выполняет следующую фоновую проверку через семь суток. Срок сохраняется после перезапуска, включая случай, когда снимок не изменился. Ручное обновление обходит этот интервал. При ошибке остаётся прежний каталог, а повторная автоматическая попытка допускается через 30 минут. В закрытом приложении загрузок нет: проверка выполняется при следующем запуске или работе приложения.

Полный встроенный JSON разбирается в фоновом потоке; до готовности синхронные читатели используют небольшой starter. Локальные описания и состав участников открываются без ожидания запроса карточки, когда этих сведений достаточно. Поиск сначала показывает локальные названия и людей, затем дополняет результаты из сети. Отдельные биографии, портреты и полная внешняя фильмография участников продолжают загружаться существующими источниками.

## Сезонные подборки

Редакторский список находится в `scripts/catalog-collections.json`. Идентификаторы должны ссылаться на существующие записи каталога; порядок сохраняется. Пример структуры:

```json
[
  {
    "id": "festival-selection",
    "title": "Фестивальная подборка",
    "startsAtUtc": "2026-10-01T00:00:00Z",
    "endsAtUtc": "2026-11-01T00:00:00Z",
    "mediaIds": ["movies:existing-catalog-slug"]
  }
]
```

Подборки появляются в фильтре приложения в заданный период. Даты необязательны; время окончания не включается. Сейчас список пуст: фактические списки премий и фестивалей ещё не заполнены.

## Состояние данных и проверка

Исходная библиотека содержит 4210 названий: 3608 фильмов и 602 сериала. В исходном снимке нет описаний и участников; ежедневное обогащение постепенно заполнит их из доступных источников. Предел времени запросов означает, что недельная загрузка клиента не гарантирует недельного обхода всех карточек. Это основной каталог приложения, а не база всех фильмов мира.

Python-проверки покрывают накопление библиотеки, сохранение метаданных, тёзок, бюджет запросов, целостность архивов, подборки и импорт ресурсов сборки. `catalog-text-tests` выполняет переносимые проверки реального транспорта, недельного расписания и локальной выдачи. Полная Windows-сборка, тесты приложения и проверки интерфейса остаются частью штатного выпуска.

## Списки наград (`awards.json`)

Победители «Оскара» (лучший фильм) и Золотой пальмовой ветви Каннского фестиваля по всем годам лежат в релизе `catalog-data` отдельным небольшим файлом `awards.json`. Приложение читает только его, не обращаясь к Wikidata: список проверяется при открытии «Актуального» не чаще раза в сутки и сохраняется на диске, без файла рубрики просто не показываются.

- Собирает файл `scripts/collect_awards.py` из Wikidata (победители с их IMDb-кодами, названиями на русском и английском, годом фильма и, если есть, постером из Wikimedia Commons). Перед записью проверяются форма, уникальность, число записей, разница между годом награды и годом фильма и несколько известных победителей; неверный ответ Wikidata останавливает запуск, а не публикуется.
- Раз в неделю и вручную его обновляет workflow `Refresh award lists`: он прогоняет офлайн-проверку (`scripts/test-collect-awards.py`), собирает список и загружает `awards.json` в релиз `catalog-data`, затем скачивает его обратно и сверяет.
- Формат: `{"schemaVersion":1,"generatedAtUtc":…,"awards":[{"id","title","titleEn","description","descriptionEn","entries":[{"year","imdbId","title","titleEn","originalTitle","filmYear","poster"}]}]}`. Победитель показывается как карточка с IMDb-кодом: описание, жанры и актёры приходят из `/api/title`, раздачи ищутся обычным образом. Если фильм уже есть в общем каталоге (по IMDb-коду), используется его обычная карточка.
- Чтобы добавить награду, допишите её в `AWARDS` в `collect_awards.py` (код Wikidata, границы числа записей, проверочные победители).
